# 双场景互动与分发接口 · v0.10

## 队友最先复用什么

页面接入：主页链接到完整 `web.html` 即可进入独立创作。单场景、融合和玩家生成物使用相同源码构建；无需把整套游戏脚本嵌入主线。需要完成通知时监听已有 `wanxiang:creation-completed` 事件，事件含 worldId 与 independent；当前不改主线结局。

分发工作流：`Node pipeline.cjs` → 编译 AI 回放样例 → `build.js` 合并素材和脚本 → 生成两单场景、两融合骨架的 web.html / world.json → 白名单 ZIP。每个 web.html 内嵌 JS、CSS、SVG、媒介缩略图与明确标记的历史成图样例，直接双击可玩。不打包服务凭证、缓存、日志与本地存档。构建依赖同级原故宫与雅典美术工程；成品运行不依赖这些目录。

## AI 和本地创作共同契约

AI 只返回受约束的 plan JSON：primary、skills、天气、时段、配色、意象、空间聚散、侧庭方向、interactionPolicy 等。AI 不直接生成坐标或任意游戏代码。客户端严格校验后统一调用 `FusionSpec.derive`，再跑可达性检查。

默认 full；no-npc 移除人物绘制和人物口吻，保留观察案/卡片/小游戏；no-games 保留人物与文化卡，跳过小游戏挑战；quiet 不注册互动且允许直接成画。UI 显式偏好优先，auto 时从提示词推断。两个融合骨架均同时装配已有文化内容，不将故宫木作复制为雅典玩法。

若新增文化包，按以下次序接入：文化来源与边界 → 建筑/空间规则 → 编译锚点 → 卡片与图像 → 可选互动与可见成果 → 成图绑定/分享外观字段 → 全组合可达性与策略检查。不要把试玩完成状态写进 WorldSpec。

## 文化与图片说明

雅典三卡分别讨论山门与地形、柱列山墙与留白、柱廊与公共停留。明确卫城与古代集市不是同一处，白色不代表古建筑原貌，多立克柱身不另设独立柱础。建筑配图为原创 SVG 示意而非历史照片、实测图或遗址导航。人物均虚构，拼合为现代观察小游戏。资料链接在卡片内，卡片正文和插画可离线阅读。

## 建议测试提示词

1. 雅典单场景：「在雅典卫城错落台地上散步，保留绕行神庙和斜向观看，在落日下与少量人物交流、读建筑图记，完成轻量观察互动后定格。」
2. 故宫主融合：「故宫门院为骨架，两翼纵廊不占中轴，白石神庙和柱廊进入侧院与远景，保留两种文化图文卡和少量互动。」
3. 卫城主融合：「卫城为主，错落台地、神庙周围留白，让红檐共创台与柱列相遇，东侧取景，少量人物和可选互动。」
4. 排除测试：「雅典卫城落日，保留文化卡，不要 NPC，不要小游戏。」应进入纯观赏；也可用互动下拉框显式测试各策略。

## 验证与边界

`node verify.cjs` 运行成品脚本的多布局可达、互动、成画、分享与历史包验证。`python verify_api.py` 使用模拟 Responses 响应检查协议，不联网、不读认证。浏览器补充实际移动、E 阅读、卡片与小游戏操作。本次不重新检查网络，也不调用付费图像/文本生成。新实时服务端口 8326，旧版 8324 独立保留。


## 页面信息层级与生成方式（2026-10-31）

首页统一使用「让想象成境」，竖排「寻古意，入新境」；主区保留场景原型、空间骨架、生成方式、提示词和生成按钮。「更多设置」收纳文化技能和互动偏好，「更多作品与导入」收纳历史转绘与 JSON 导入。折叠只影响展示，原控件 ID、默认技能和生成参数保持可复用。

每次加载页面默认「本地生成」；服务状态检测只更新提示，不得自动切成 AI，也不得覆盖玩家正在选择的模式。只有玩家主动选择「AI 实时生成」并点击生成，才请求 AI 编排。作品页的图像转绘仍是独立的显式操作。

作品页集中展示取景、媒介与保存操作；作品信息、外部图片导入、原图和提示导出收进折叠区。转绘来源、服务状态、错误信息及费用说明保留可见。修改入口为 src/ui.html、src/game.js、src/artwork-ui.html、src/artwork.js；运行 pipeline.cjs 同步全部 web.html 与 ZIP，避免只改首页而分发旧页面。


## 创造模式开发交接包（2026-10-31）

作品页标题统一为「把这一境，定格成画」。开发交接发送「万象灵境-v0.10-创造模式开发接入包.zip」，不是试玩合集。包内包含可修改源码、文化包、完整素材、构建与服务脚本、构建所需的原始美术依赖和旧版本回归样本；根目录「接入说明.md」提供接入与配置步骤。

`integration/home-entry.html` 是主游戏入口链接示意；`integration/host-example.html` 是可运行的同源 iframe 宿主示例。iframe 的 src 默认 `../index.html`，部署到队友工程后按实际路径调整。不要把两套全局 G 直接合并到同一个 window；推荐独立页面或 iframe。

完成事件是创造模式自身 window 上的 `wanxiang:creation-completed`，detail 为 `{worldId, independent:true}`，不会自动向 iframe 父窗口冒泡。宿主在 iframe load 后监听 `iframe.contentWindow`；仅正式观景台定格触发，按 P 预览不算完成。需要作品数据时读取 `FusionExplore.artifact()`（可分享包），需要当前试玩状态时读取 `getState()`，导入作品使用 `importPackage(artifact)`；`showCreation()` 返回创作首页。不要直接读写内部 G 来耦合主线。

AI 接口为同源 `/api/status`、`/api/world/generate`、`/api/artwork/render`。当前 Python 服务只提供创造模式页面和接口，不是主游戏通用静态服务器。主游戏同源部署时将这几个 API 路由接入或代理到自己的后端，并同步 Host/Origin/令牌校验；不要把 API 密钥放进前端、iframe 参数或分享包。跨源接入需由队友另加来源校验的消息桥，当前未提供跨域授权。
