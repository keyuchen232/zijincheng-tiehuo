# 万象灵境 v0.10 · 创造模式开发接入

这是给主游戏开发者的完整接入工程。请先完整解压整个文件夹，不要只取试玩 HTML。先读本文件，再读根目录的交互.md。

## 先打开与定位文件

- `源码工程/融合探索-demo-v0.10-双场景互动适配/index.html`：当前完整、可离线打开的创造模式。
- 同目录 `src/`：页面、空间编译、绘制、文化卡、NPC/小游戏、作品页源码。
- 同目录 `packages/` 与 `skills/`：故宫/雅典文化包、空间规则和技能说明。
- 同目录 `assets/`：图片与历史 AI 示例，构建会内嵌进成品。
- 同目录 `integration/host-example.html`：主游戏同源 iframe 接入示例。
- 同目录 `serve_ai.py`、`world_api.py`：文本规划和实景图生图服务接口。
- `源码工程/athens-city-v2.0.0/`、`源码工程/zijincheng-tiehuo-v1.0.0/`：构建实际使用的原始引擎、美术和 CSS 依赖，已经随包带齐。不是这两个历史游戏的完整发行版。
- `源码工程/融合探索-demo-v0.9-取景与建筑图记/`：仅供验证迁移的历史 world.json 样本。
- `tools/image-api/`：图片 API 包装器及其调用的 CLI 源码，已经随包带齐，不要求安装 Codex。
- `文件清单.json`：所有交付文件的大小与 SHA256，用于检查解压完整性。

## 接入主游戏创造模式

最小方式：在主游戏首页的「创造模式」按钮跳转到本工程 `index.html`；部署时可改名为 `creation/index.html`。这个 HTML 已包含运行所需的脚本、图片和文化卡，离线不需要后端。

希望保留主游戏导航时：使用 `integration/host-example.html` 中的 iframe 方式，按项目位置调整 src。推荐同源部署，保留创造模式自己的 window 与存档，避免与主游戏的全局 G 冲突。示例自带进入/返回按钮和完成事件接收。浏览器 file:// 对 iframe 同源访问存在限制；要测试事件，在工程目录运行 `python -m http.server 8330 --bind 127.0.0.1`，然后打开 `http://127.0.0.1:8330/integration/host-example.html`。

事件：`wanxiang:creation-completed` 在创造模式的 window 上触发，detail 只有 worldId 和 independent。iframe 不会向父页自动冒泡，必须在 load 后监听 contentWindow。观景台正式定格才触发，按 P 预览不触发。当前只用于作品通知，不参与主游戏结局。

现有接口：`FusionExplore.artifact()` 取得分享包，`getState()` 取得规格与试玩进度，`importPackage(artifact)` 导入作品，`showCreation()` 返回创作界面。先等待 iframe load 再调用；数据结构和进度分离约定详见交互.md。

## 修改与重新构建

环境：Node.js 20+（推荐当前 LTS），Python 3.11+。本项目没有 npm 依赖，无需 npm install。只打开成品 HTML 不需要这两个环境。

在 `源码工程/融合探索-demo-v0.10-双场景互动适配/` 打开终端：

```powershell
node build.js
node pipeline.cjs
node verify.cjs
python verify_api.py
```

build 生成 index.html；pipeline 同步全部场景包、交互文档和试玩 ZIP；verify 检查真实成品脚本，verify_api 只使用模拟响应、不调用付费接口。也可以从交付根目录运行「构建全部.ps1」，一次执行这四步。Python 不在 PATH 时将 WANXIANG_PYTHON 设为实际 python.exe 路径。

修改 src 后请重新构建。不要只修改发布目录的 HTML，它会在下次构建时覆盖。请保留本包的相对目录关系，或者自行调整 build.js 的依赖路径。

## AI 服务配置（接收者自己的认证）

本地生成和像素成画无需任何 API 配置。AI 文本规划、AI 图片转绘均需要队友自己的服务与额度，包内没有密钥、真实 config.toml 或你的本机认证。

Python 图像依赖：在交付根目录运行 `python -m pip install -r requirements.txt`。仅文本规划使用 Python 标准库；图像 CLI 需要 openai 与 Pillow。

把 `本地配置/config.example.toml` 复制为同目录 `config.toml`，填写自己的服务商 base_url、文本模型和凭证环境变量名称。示例中只有环境变量名，密钥在本机设置，不要写进前端或提交给队友。

```powershell
$env:WANXIANG_API_KEY = '在本机填入接收者自己的密钥'
.\启动本地服务.ps1
```

根目录启动脚本只对当前进程指定本包的配置目录，后台启动 127.0.0.1:8326；加 `-NoBrowser` 可不打开浏览器。停止时运行工程中的「停止AI绘景.bat」。本包不自带 Node/Python 二进制，图像依赖需按上文安装。

文本服务也支持 WANXIANG_TEXT_BASE_URL、WANXIANG_TEXT_API_KEY、WANXIANG_TEXT_MODEL 独立配置，优先于 TOML；图像包装器读取 TOML 的 provider 与 env_key，使用 gpt-image-2 的 images/edits（服务商须支持尺寸与图片编辑）。没有配置时，本地模式仍可正常运行。

接口为同源 `/api/status`、`/api/world/generate`、`/api/artwork/render`，后两者要求来自状态接口的 X-Wanxiang-Token 及本机 Host/Origin 校验。Python 现有服务只提供创造模式页面与接口；接入主游戏服务器时，需要队友迁移这些路由或设置代理并适配校验。不能只把静态文件上传后就认为 AI 接口已部署，也不要为了接入而取消令牌和来源校验。当前方案面向本机，不是公网多人后台。

## 已完成与当前边界

已提供两个单场景、两个融合宿主版本、文化技能、本地/AI 规划、少量人物与互动、建筑图文卡、完整取景、像素成画、实景图生图接口、分享与导入。默认本地，只有主动选择 AI 并点击生成才请求；图像转绘另需主动点击。

没有布达拉宫、泰晤士河或视频功能；任意建筑输入与通用小游戏生成仍是后续展望。文化建筑与配图为当代虚构转译，不是历史复原。样例转绘是明确标记的历史结果，不代表每个新场景都已有 AI 成图。

接手后建议先接通主游戏入口、同源 iframe 返回与作品通知，再接入自己的文本/图片 API，最后按交互.md 验证两单场景及两种融合。不要把创造模式的完成状态写入主线结局。

## 主游戏侧的改动（本仓库）

- 主游戏「创造模式」按钮在新标签页打开 `creation/index.html`（整窗体验），`_blank` 打开、失败时退回同源 iframe。
- 作品完成通知不仅监听窗口事件，还通过 `postMessage` + `localStorage('wxl.creation.done')` 兜底，新标签页拿不到窗口句柄也能收进 `G.save.data.creations`。
- **浏览器直连 AI**：`index.html` 里内联了一段 shim，拦截 `/api/status` 与 `/api/world/generate`。本机 `python serve_ai.py` 在跑就走本机服务；没跑（或部署在静态站）就由浏览器直接调 OpenAI 兼容接口生成结构化方案，字段校验与 `world_api.py` 一致（同一份系统提示词、同一套枚举与技能约束）。实时图像转绘 `/api/artwork/render` 仍需要本机服务，静态站保持「离线 · 可导出原图」。
- 因此「生成方式」默认会切到「AI 实时生成」，生成失败时页面会回退提示，可手动切回「本地生成」。
