## 1. 这份文档解决什么问题

现状不是"没有关卡"，而是**六个节点里八个谜题全部是对话框选项**：点一下，弹一段话，对了就过。世界里什么都没变。

而 v0.3 定的标准是：

1. 每个节点配一个**动作**；
2. 动作的规则 = 它想讲的道理（换个题材就不能用）；
3. 失败要在**世界里看得见**（砖缝歪、柱子塌、门不亮），不是弹窗。

抽查代码可以确认差距在哪：

| 关卡 | 已有谜题 | 现在的形态 | 世界的反应 |
|---|---|---|---|
| 关 1 午门 | `wumen.registration` | 一次三选一 | ✅ 有：`js/art/wumen.js:58` 读 `gridDx`/`gridBoth` 画两套网格错位 |
| 关 2 太和殿 | `taihe.labels` | 三块牌逐个"挪 / 留" | ❌ 无：`js/art/halls.js` 的画笔一个都不读 `vars` |
| 关 3 乾清宫 | `qianqing.loadtest` | 两材料 × 三方法，塌了 toast | ❌ 无 |
| 关 4 修复台 | `repair_bench.evidence`、`repair_bench.relic` | 选卡 / 留白、改判 | ❌ 无 |
| 关 5 御花园 | `creator.review` | 指出错标签 → 改回 | ❌ 无 |
| 关 6 神武门 | `shenwumen.verify` | 配对 + 三句话 | ❌ 无 |

**所以这一版的工作不是重做六关，是给六关各自接上"世界的反应"。** 数据、判定、文案骨架都保留，改的是三件事：动作分几步、哪个变量变、哪个画笔读它。

## 2. 六条设计不变量

写任何一关都必须满足。违反了就不是这个设计。

1. **一关一个动作。** 一关里不出现两种不同性质的操作（比如又连又选又拖）。同一个动作可以在多个物体上重复。
2. **错答案必须先看起来对。** 玩家第一次选错的概率要高于选对。难度来自"看起来对的那个是错的"，不来自倒计时、不来自反应速度、不来自运气。
3. **后果落在画面，不落在弹窗。** 判定失败时不弹"回答错误"，只改 `vars`，让 A 的画笔把后果画出来。文字只用来**在事后点破**，不用来宣布失败。
4. **不扣分、不锁死、可重试。** 失败只是回到本关的起点，已获得的来源卡不回收。
5. **痕迹留下。** 裂纹、乱码、塌过的柱子，一旦产生就保留到本关通关（甚至通关后）。**痕迹是本局最好的叙事**，也是最终校准记录卡上的内容。
6. **文字只在 `data/script.json`，`js` 里零中文。** 这条现在还没做到（见 §9 工单 G-1），本设计新增的所有文案一律走 key。

**允许的机制只有三种**（地基已经有，不需要动 `js/mod.js`、`js/stage.js`）：

| 机制 | 写法 | 能做什么 |
|---|---|---|
| 世界交互点 | `data/maps/*.js` 的 `spots[]`，`puzzle` 走玩法、`inspect` 看一眼 | 走位、选择、连点 |
| 对话框选项 | `G.dialog.ask` / `api.ask` | 一次判断，2–5 个选项 |
| 变量驱动画面 | `api.setVar(k, v)` → 画笔读 `scene.vars` | 砖缝、裂纹、门亮、投影位移 |

**明确不做**：不新建地图、不新建 canvas、不改 `js/mod.js` 的 api。需要临时面板时用 `api.overlay(el)`（已有，会锁输入并计入 `G.overlayDepth`）。

### 关 1 · 午门：原点之争

> 一句话：**玩家必须先"想对齐"，才能听懂"不能为了对齐而挪自己"。**

**玩家走进来看到什么**
午门广场。地面叠着两套网格：金色细线是故宫中轴网格（以门洞中心为原点），青灰色是卫城网格，整体偏右约 18 px。肉眼一看就是"没对齐"。狄奥提玛站在门洞前，不说话。

**动作（三段，全部在同一个 `puzzle` 里）**

| 段 | 玩家做什么 | 世界怎么反应 | 判定 |
|---|---|---|---|
| A 看 | 走到门洞前的交互点 | 两套网格的偏移被点名，她被问"哪一层在动" | 无判定，纯交代 |
| B 选原点 | 三个候选原点选其一 | 网格做 0.4 s 吸附（`gridDx`/`gridBoth` 直接跳变，不做 tween，省一次 repaint） | 只有 A 通过 |
| C 读 | **不出现对话框**，静帧 1.2 s，然后问"哪里不对" | 见下表 | 选 C 后必须答对“砖缝”才能通过 |

| 选项 | 变量 | 世界里的后果 |
|---|---|---|
| A 午门门洞中心 | `gridDx=0`，`gridBoth=0` | 青色网格平移过去贴住金色网格，故宫一格没动。**通过** |
| B 太和殿月台中心 | `gridDx=18`，`gridBoth=14` | 两套网格一起被拖走，月台与殿身脱开（`terraceGap=1`） |
| C 投影自身中心 | `gridDx=0`，`gridBoth=-18`，`seamShift=1`，`nailShift=1`，`shadowShift=1` | **看起来完全对齐**，但金色网格被拖走 18 px：砖缝错位、门钉间距不对、投影影子方向歪 |

**为什么错答案像对的**
B 和 C 都"动了"。区别是 B 动得明显（玩家会觉得"这不对"），C 动得**刚好对齐**——玩家的眼睛在比对两套网格的边缘，而 C 让边缘完美吻合。**只有把注意力从"两套对不对上"移到"我们自己的东西有没有动"才能发现。** 这一关考的是注意力的对象，不是观察力。

**痕迹**
- 选 C 后，若最终答不出"砖缝"，`seamShift`/`nailShift` 复位为 0，网格回到未对齐状态（可重选）。**不留永久痕迹**——这一关的痕迹是"那一秒的沉默"，不是画面损伤。

**通过条件**
`choice === 'A'` **或**（`choice === 'C'` 且第二问答"砖缝"）。选 C 但第二问答错 → 复位重来，不通过。

**数据契约**

```js
/* data/maps/wumen.js —— vars 追加三项（gridDx/gridBoth 已有） */
vars: {
  gridDx: 18,        /* 卫城投影相对故宫的错位，0 = 已对齐 */
  gridBoth: 0,       /* 两套一起被拖走的量，非 0 = 故宫被挪了 */
  seamShift: 0,      /* 砖缝错位 0|1（选 C 时 = 1） */
  nailShift: 0,      /* 门钉间距异常 0|1 */
  terraceGap: 0,     /* 月台与殿身脱节 0|1（选 B 时 = 1） */
  view: '',          /* ''|'silent' —— 'silent' = 静帧，盖掉 HUD 提示 */
}
```

```js
/* spots：现有三个不动，只补「读数」这一问由玩法内部弹，不占 spot */
{ id: 'wumen.origin', x: 320, y: 486, r: 68,
  labelKey: 'ui.hud.interact', puzzle: 'wumen.registration',
  when: { notDone: ['wumen.origin'] } }
```

| 谁 | 改什么 | 怎么改 |
|---|---|---|
| A | `js/art/wumen.js` | `wumen.grid` 已读 `gridDx`/`gridBoth`；新增读 `seamShift` 画砖缝错位（广场地砖的缝按 18px 错开）、`nailShift` 让 `wumen.gate` 的门钉间距从 34 px 变 40 px、`terraceGap` 让月台整体下沉 4 px。全部读 `scene.vars`，只画不写 |
| A | `js/stage.js`（不用改） | 静帧用已有的 `screenPainters`：`scene.screenPainters = ['wumen.silent']`，`wumen.silent` 在 `view==='silent'` 时画一层压暗 + "（静帧）"细字。**这是地基里 `js/stage.js:194` 明确预留的扩展点** |
| C | `js/mods/wumen-registration.js` | 由"一次 ask"改成三段：`api.ask` → 设 vars → `setTimeout(1200)` 静帧 → 第二次 `G.dialog.ask` 问读数 → 判定 → `api.pass({choice})` |

**文案要点（给 B）**
- 开场要说"哪一层在动"，不说"选个原点"——先给问题，不给任务说明。
- 选 C 之后那句必须是**先描述事实、再下判断**：「……你移动的是故宫。」（句号后停一秒）「为了让两套东西对上，你挪了自己。这不是校准。」
- 选 A 通过时不要夸"答对了"。要说的是她**第一次让步**：「好。你没动它。」→「在雅典我们管这叫配准。在你们这儿它叫什么不重要——重要的是你刚才没做的事。」
- 玩家独白 ①：「它没动。动的是另一套。」（独立成段，界面不显示说话人）
- 通过发卡：`sc_axis`（故宫中轴 · 本体不动）。

**验收**
- [ ] 选 C 后 `scene.vars.seamShift === 1`，且砖缝在画面上肉眼可见地错开
- [ ] 静帧期间没有任何对话框、没有交互提示，且 `G.isWorldPaused()` 为真（输入不穿透）
- [ ] 选 C 后第二问答错 → `gridDx` 复位为 18，可重选，且不重复发来源卡
- [ ] 三个选项的后果互不相同（B 是月台脱节、C 是砖缝错位、A 是青色网格平移）
- [ ] 60–75 秒内，只看画面就能分出三者的差别

### 关 2 · 太和殿月台：标签归位

> 一句话：**先问"这块属于谁"，再动手。**

**玩家走进来看到什么**
太和殿月台。三块说明牌悬空错位，其中一块压在一块"希腊化"的石雕上——**它看起来最不对劲，其实本来就是故宫的**。月台边上有三块不起眼的石砖（图层石），踩上去会切换看到的层。

**动作**

| 步 | 玩家做什么 | 世界怎么反应 |
|---|---|---|
| 1 | 走到月台中央的交互点 | 她交代：三块牌子，两块被我盖错了，还有一块本来就没错 |
| 2 | **踩石作层**（`taihe.layer.stones`） | `layerStones=1`：帕特农山墙投影变半透明（alpha 0.15），底下那块石雕显出来是故宫原物 |
| 3 | 依次处理三块牌子 | 每块只有两个选择："挪到「<目标>」" / "留在原地不动" |
| 4 | 全对后 | 收束 + 记 `labelsDone=3` |

| 牌子 | 内容 | 正确 | 错了会怎样 |
|---|---|---|---|
| p1 | 帕特农东山墙 | 挪到投影位置 | `labelGlitch=1`，那块栏杆的说明变乱码 |
| p2 | 伊瑞克提翁女像柱廊 | 挪到柱廊投影 | 同上 |
| p3 | 故宫太和殿月台 | **留在原地** | `labelGlitch=1`：这段栏杆的说明变乱码，但她会提示"那块是你们自己的石头" |

**为什么错答案像对的**
p3 压在一块希腊风格的石雕上，**视觉上就是"贴错了"**。而 p1/p2 位置其实不显眼。玩家如果按"哪里看着别扭点哪里"来做，会正好把唯一正确的一块挪走。

**痕迹**
`labelGlitch=1` 保留到本关结束，也可在本关内改回（再处理一次 p3）。**这里允许带着乱码通关**——痕迹是记录，不是惩罚。最终它出现在校准记录卡上（"1 处误标"）。

**数据契约**

```js
vars: {
  layerStones: 0,   /* 石作层 */
  layerImages: 1,   /* 图像层（默认开） */
  layerLabels: 1,   /* 标签层（默认开） */
  labelGlitch: 0,   /* 误标留下的乱码 0|1 */
  labelsDone: 0,    /* 已处理牌子数 0..3 */
  keepSteps: '',    /* 关 2 收尾的选择（本关内可用；跨场景要另存布尔 flag，见 §5.1.1） */
}
/* 收尾选择必须存成"每个选项一个布尔 flag"，否则记录卡读不到选了哪个： */
G.save.flag('keep.keep', true)  /* 或 keep.note / keep.drop */
```


**注意：`when` 不加条件，图层石永远可踩（随时来回切）。** 三个玩法模块可以写在同一个文件 `js/mods/taihe-layers.js` 里注册三次，不必三个文件。

| 谁 | 改什么 | 怎么改 |
|---|---|---|
| A | `js/art/halls.js` | `hall.terrace` 读 `layerStones`/`layerImages`：`layerStones===1` 时把投影层 alpha 降到 0.15、把底下石雕全画出来；读 `labelGlitch` 在栏杆上画 3–4 行错位像素（乱码） |
| A | `data/maps/taihe.js` | 加三个图层石 spot（上面片段）+ vars 五项 |
| C | `js/mods/taihe-layers.js`（新） | 三次 `G.mod.puzzle('taihe.layer.stones', {open})`，`open` 里只 `api.setVar(...)` + `scene.repaint()`（地面层烘焙过，必须 repaint）+ `api.pass()` |
| C | `js/mods/taihe-labels.js` | 判定不变；在 `p3` 挪错的分支里加 `api.setVar('labelGlitch', 1)`。**注意不要再 `pass` 前清零** |

**文案要点（给 B）**
- 三块牌的名字要写得像真的导览牌（"帕特农东山墙 · 东端山花"），不要写"错误标签 1"。
- 踩图层石时不要弹说明，只给一行 HUD：「现在是石作层」。
- 误标 p3 的那句必须是**替玩家把话说清**：「那块是你们自己的石头。」（顿）「它只是长得像我带来的东西。」
- 全对：「你一动手，先问的是'这属于谁'。这很好。」
- 收尾 `taihe.keep` 三项皆可（写进规则 / 记一笔 / 不写），不打分，但选了什么要存进 `keepSteps`，结局卡要显示。

**验收**
- [ ] 不踩任何图层石也能通关（P1 才强制）
- [ ] 踩石作层前后，画面差异肉眼可见（投影变淡、底下的石雕显出来）
- [ ] 误标 p3 → `labelGlitch=1` 且画面有乱码；再处理一次能改回 0
- [ ] 带乱码通关被允许，且 `keepSteps` 被记住
- [ ] 40–60 秒内完成

### 关 3 · 乾清宫：承重实验

> 一句话：**不是比谁先进，是问材料接受什么。**

**玩家走进来看到什么**
乾清宫前。六根女像柱投影撑起檐部，第七根是故宫的木柱。风过时檐口有轻微起伏。

**动作**

| 步 | 玩家做什么 | 世界怎么反应 |
|---|---|---|
| 1 | 走到檐下交互点，先给**石柱**选连接方式（榫卯 / 铅灌铁销 / 直接叠压） | 选中即"加载"：2 秒内檐部下沉或稳住 |
| 2 | 再给**木柱**选一次 | 同上 |
| 3 | 两次都站稳 | 收束：她补那句"你以为我们不用连接件" |

| 连接方式 | 石柱 | 木柱 |
|---|---|---|
| 榫卯 `tenon` | ❌ 石材受剪，卯口崩裂，檐部塌 | ✅ 咬合承压 |
| 铅灌铁销 `dowel` | ✅ 通过 | ❌ 木会胀缩，销钉被顶松 |
| 直接叠压 `dry` | ✅ 石承压 | ❌ 摩擦不足，柱头滑移 |

**为什么错答案像对的**
玩家第一次几乎一定给**木柱**选榫卯——因为他刚在石柱上被榫卯教训过，会推断"榫卯是错的"。设计上把顺序定死为**先石后木**，就是为了让"同一个答案在两种材料上给出两种结果"这件事由玩家自己撞出来。**如果玩家两问都给同一个答案，必然错一半。**

**痕迹**
塌过的那根柱子 `crack=1`，裂纹保留到本关通关。塌的过程要看得见：`sag` 由 C 分四档推（0.25 / 0.5 / 0.75 / 1），A 的画笔读它把檐口往下掰，1.2 秒后复位，**裂纹留着**。

**数据契约**

```js
vars: {
  tested: 0,          /* 已站住的材料数 0..2（已有） */
  stoneMethod: '',    /* 石柱最终方法（已有） */
  woodMethod: '',     /* 木柱最终方法（已有） */
  sag: 0,             /* 檐部下沉 0..1，塌陷动画用，结束复位 0 */
  crack: 0,           /* 塌过的柱子留下裂纹 0|1，直到通关 */
  dust: 0,            /* 尘土粒子 0|1，随 sag 一起 */
}
```

C 侧动画（不需要改地基，`props` 每帧重画，所以 `setVar` 立即生效）：

```js
/* 塌陷：四档推进，最后复位；crack 保持 */
const steps = [0.25, 0.5, 0.75, 1];
steps.forEach(function (v, i) {
  setTimeout(function () { api.setVar('sag', v); api.setVar('dust', 1); }, i * 150);
});
setTimeout(function () {
  api.setVar('sag', 0); api.setVar('dust', 0); api.setVar('crack', 1);
}, 1800);
```

| 谁 | 改什么 | 怎么改 |
|---|---|---|
| A | `js/art/halls.js` | `hall.terrace` 读 `sag` 把檐口按 `sag*10` px 下移并左右微摇；读 `crack` 在对应柱身画 2–3 道折线；读 `dust` 画一层低 alpha 的土色噪声 |
| A | `data/maps/qianqing.js` | vars 加 `sag`/`crack`/`dust`；柱子摆位保持六石一木 |
| C | `js/mods/qianqing-loadtest.js` | 判定不变（`outcome[material][method].ok`）；失败分支加上面的塌陷动画 + `crack`；成功时 `api.setVar('stoneMethod'/'woodMethod')` 已有 |

**文案要点（给 B）**
- 开场只说身体关系，不说材料学：「六根少女替你扛着屋檐。第七根……是你们的柱子。」

### 5.1.1 一个必须避开的坑：`G.save.flag()` 只有布尔

`js/core.js:166-171` 的 `flag(k, v)` 里写的是 `this.data.flags[k] = !!v` —— **传字符串会被压成 `true`，读回来就只有 `true`，没有值**。

所以下面两处现有代码是失效的，记录卡拿不到具体选择：

- `js/mods/repair-relic.js:49`：`G.save.flag('judged.R07', 'fusion')` → 存进去的是 `true`
- `js/mods/taihe-keep.js:38`：`G.save.flag('keep.steps', choice)` → 存进去的也是 `true`，**玩家选了哪一项丢失了**

**本设计的规矩：跨场景的选择一律拆成"每个选项一个布尔 flag"**（同场景内的信息走 `scene.vars`，不要用 flag）：
