# 模块接口 · 三个人怎么同时开工

> 这份文档是给你队友看的。它不讲剧情，只讲**边界**：
> 谁拥有哪个文件、谁调用谁的什么、怎么知道自己的活接上了。
>
> 看完这一页就能开工。遇到这里没写的情况，先问，别自己改地基。

---

## 0. 一句话

游戏现在不是「一个项目」，是**一座地基 + 五个抽屉**：

```
地基（谁都不改，只调用）
  js/str.js    读文案        G.str
  js/mod.js    登记与拼装    G.mod
  js/stage.js  把关卡数据变成场景
  js/cut.js    演过场        G.cut

抽屉（各自拥有，互不覆盖）
  data/script.json   所有文字          ← B
  js/art/*.js        画笔              ← A
  data/maps/*.js     关卡坐标          ← A
  js/mods/*.js       小游戏与交互事件   ← C
  data/cuts/*.js     开场/过场/结局     ← C（字找 B、画找 A）
```

**并行工作的全部前提只有一条：没有人需要改别人的文件，也没有人需要改地基。**

如果你们发现「必须改地基才能做」，那就是地基漏了接口 —— 提出来，加接口，不要各自 hack。

## 3. 地基 API 速查

### 3.1 `G.str` —— 读文字（B 的产物的唯一入口）

```js
G.str.get('nodes.wumen.objective')      // 取值；缺失返回 ⟪key⟫，不崩
G.str.get('ui.hud.look', { name:'门钉' }) // {name} 插值
G.str.has('nodes.wumen.enter')          // 有没有这段
G.str.dialog('nodes.wumen.enter')       // → [{name|narrator, text, speed}]，可直接丢给 G.dialog.show
G.str.seg('sourceCards.sc_axis.lines')  // → 原始数组（字卡用）
G.str.puzzle('wumen.registration')      // → puzzles 里的整块
G.str.options('puzzles.wumen.registration.options') // → [{label, value, desc}]
G.str.who('diotima')                    // → { name:'狄奥提玛', color:'#cbb283' }
G.str.all('objects')                    // → 整段数组
```

**规矩**：代码里不许出现中文句子。所有面向玩家的字，一律走 key。

### 3.2 `G.mod` —— 登记与拼装

```js
G.mod.register({ kind:'painter',  id:'wumen.gate', draw:function(ctx,prop,scene){} });
G.mod.register({ kind:'puzzle',   id:'wumen.registration', open:function(api){} });
G.mod.register({ kind:'cutscene', id:'wumen.intro', steps:[...] });
G.mod.register({ kind:'map',      id:'wumen', ... });

G.mod.has('cutscene','wumen.intro')   // 有没有登记
G.mod.test({ done:['a'], notDone:['b'], flag:{x:true} })
G.mod.paint('wumen.gate', ctx, prop, scene)
G.mod.cut('wumen.intro', done)        // 播过场，播完回调
G.mod.go('taihe')                     // 切到下一关
```

### 3.3 `G.cut` —— 过场放映机

```js
G.cut.play('wumen.intro', function(){ /* 播完 */ });
G.cut.seen('opening')   // 看过没有（存在存档 flag cut.opening）
G.cut.active            // 正在播
```

### 3.4 `G.StageScene` —— 不需要你调用

只有 `G.mod.go(mapId)` 会创建它。

## 4. A · 美术与关卡

### 4.1 你交付两样东西

**① 画笔** —— 一个纯函数，往 canvas 上画，不读存档、不发请求：

```js
G.mod.painter('wumen.gate', function (ctx, prop, scene) {
  // ctx 已经是 2D context
  // prop = 地图里那个对象（带 x/y/…）
  // scene = 当前场景，可以读 scene.vars
});
```

坐标系：`x` 水平（0 = 最左），`y` 纵向（0 = 最上，越大越靠近镜头）。
**画物件时，`(prop.x, prop.y)` 就是这个物件的「脚底中点」** —— 和 `G.art.drawActor` 的约定一致。所以画一座门，门的中线要落在 `prop.x` 上，门的底边要落在 `prop.y` 上。这样 baseY 排序（站到门后被门挡住）才会自动正确。

可以直接用的现成画笔（省一半时间）：

```js
G.art.paving(ctx,x,y,w,h,base,alt,seed,tile)   // 铺地面
G.art.drawGate(ctx,x,baseY,w,opts)             // 城门（sprite 按 0.5 缩放）
G.art.wallH / wallV / tree / pine / willow / lantern / lion /
G.art.vat / sundial / crane / sign / bench / rock / bridge / water
G.art.drawActor(ctx,x,y,{dir,frame,moving,time,palette,accessory,scale})
G.art.palette.*, G.art.shadow(), G.art.dither(), G.art.glow()
```

**② 关卡数据** —— 一个 map 对象。字段全表（`js/stage.js` 只认这些）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | 必须是 `wumen/taihe/qianqing/repair_bench/creator/shenwumen` 之一 |
| `title` `sub` | | 没有 `script.json` 时的兜底名 |
| `size` `{w,h}` | ✔ | 场景尺寸，640×1120 是竖屏基准 |
| `spawn` `{x,y}` | ✔ | 出生点 |
| `camera` `{lookAhead}` | | 默认 42 |
| `clock` `'08:30'` | | HUD 上的时辰 |
| `dayGrade` | | `false` 关掉全局色调 |
| `ambient` | | `'palace'` / `'night'` 等环境音 |
| `night` `nightStrength` | | 夜景遮罩 |
| `vars` `{...}` | | **C 改画面只能改这里** |
| `background` `'#0b0907'` | | 离屏底色的填充色 |
| `ground` `[{painter,x,y,w,h}]` | | 烘焙进地面（不参与遮挡，最省性能） |
| `solids` `[{x,y,w,h}]` | | 碰撞盒 |
| `props` `[{painter,x,y,baseY?}]` | | 参与 baseY 遮挡 |
| `npcs` `[{x,y,painter?,dialogKey,labelKey?,r?}]` | | 有 `painter` 就自绘，否则用现成 NPC |
| `spots` `[{id,x,y,r,puzzle\|inspect,when?,labelKey?}]` | ✔ | 交互点。`puzzle` 找 C，`inspect` 是通用「看一眼」 |
| `lights` `[{x,y,r,color,a}]` | | 光斑 |
| `marker` `{x,y,when?}` | | 目标箭头 |
| `foreground` `[{painter,...}]` | | 画在角色之上（屋檐、雾、扫描线） |
| `enterCut` `'wumen.intro'` | | 进场播哪段过场（**写了就不播 `nodes.<id>.enter` 的对话**） |
| `enterKey` `objectiveKey` `completeKey` | | 覆盖默认文案 key |
| `exitCut` | | 通关后、切下一关之前播的过场 |
| `next` `'taihe'` | | 下一关 |

最小可跑的例子就是 `data/maps/wumen.js`，照抄结构改坐标即可。

### 4.2 立绘（过场要用，也是你的活）

C 的过场里写 `{ t:'portrait', who:'diotima' }`，引擎会去找画笔 `portrait.diotima`：

```js
G.mod.painter('portrait.diotima', function (ctx, prop, scene) {
  // 画布固定 240×360
  // 原点 (0,0) = 脚底中心，所以人物往上画是负 y
  // prop = { w:240, h:360, who:'diotima' }
});
```

没画也不崩，只是过场里少一张画（控制台会提醒）。建议先画狄奥提玛一个人的半身像，够用整局。

```bash

```

它检查：地图引用的 `painter` 是不是都有登记、`inspect` 的物件 id 在不在 `script.json`、`enterCut` 的过场名在不在。

## 5. B · 剧本与文案

### 5.1 你只改一个文件

`data/script.json`。改完：

```bash
node tools/build-data.mjs     # 生成 data/script.js（双击 file:// 打开时的兜底）
node tools/check-modules.mjs  # 检查有没有引用到不存在的 key
```

### 5.2 结构

```
meta        nodeOrder 六节点顺序、notes
characters  diotima / player / narrator / system   ← who 只能用这里的 id
ui          title buttons hud panel toast          ← 界面上的字
chapters    六章名
nodes       wumen / taihe / qianqing / repair_bench / creator / shenwumen
              ├ name / sub / objective
              ├ enter[]        进场对白
              └ hint           卡住时的提示
puzzles     wumen.registration / taihe.labels / qianqing.loadtest /
            repair_bench.evidence / creator.review / shenwumen.verify
objects     12 个 obj_*   ← 物件名、描述、交互对白
sourceCards 6 张 sc_*     ← 来源卡（claim / notClaim / refs / needsVerify）
codex       10 条 cx_*    ← 图鉴
cuts        opening / wumen_intro …  ← 过场文字（key 由 C 的 steps 引用）
ending      lines[] + afterword[]
shareCard   结算卡
```

### 5.3 三条硬规矩

**① 对白行统一是 `{ who, text }`**，`who` 只能取 `characters` 里的 id。
`narrator` 会渲染成「手记」样式，`diotima` 会带她的名字和颜色。

```json
{ "who": "diotima", "text": "……你看地上的线。它们不重合。" }
```

**② key 一旦被代码引用就不要改名。**
`nodes.wumen.enter`、`puzzles.<key>.options`、`objects.obj_*`、`ui.hud.*` 这些是被代码按名字取的。
要改先在群里说，或者只改 `text` 不改 key。

**③ 不许在 JSON 里写注释。** JSON 不支持，写了整个文件会加载失败（画面会全是 `⟪key⟫`）。
需要备注就放进 `meta.notes`。

### 5.4 过场文字的位置

C 的过场按 key 取字，你在 `cuts` 段里写：

```json
"cuts": {
  "wumen_intro": {
    "0": "午门。八点三十。……",
    "1": "别急着走进去。……"
  }
}
```

C 那边写 `{ t:'card', who:'diotima', key:'cuts.wumen_intro.1' }`。
**id 用下划线（`wumen_intro`），过场登记 id 用点号（`wumen.intro`），别混。**

## 6. C · 小游戏、交互事件、过场

### 6.1 玩法模块的形状

```js
G.mod.puzzle('wumen.registration', {
  summary: '一句话说明这个玩法（给自己看）',
  open: function (api) {
    // 打开面板 / 播对话 / 弹 DOM，随便
    // 结束时必须调 api.pass() 或 api.fail()，否则这个交互点永远不完成
  }
});
```

`api` 上有什么：

| 方法 | 说明 |
|---|---|
| `api.dialog(key, done)` | 播 `script.json` 里的一段对白 |
| `api.cinema(key, done)` | 播一段字卡（`G.cinema`，纯文字） |
| `api.cut(id, done)` | 播一段过场（有画面、有立绘） |
| `api.ask(puzzleKey, cb)` | 把 `puzzles.<key>` 变成一次选项问答，`cb(value)` |
| `api.setVar(k,v)` | 改 `scene.vars` → **A 的画笔下一帧就会画成新的样子** |
| `api.toast(text, kind)` | 右下角提示；`kind` 用 `'warn'` / `'bad'` / `''` |
| `api.overlay(el)` | 锁输入并显示一个 DOM 面板（**只有要弹自定义面板才用**） |
| `api.release()` | 解锁（`pass`/`fail` 会自动调） |
| `api.pass(result)` | 这个交互点完成 → 写存档 → 通知关卡判定 |
| `api.fail(key)` | 失败：解锁 + 提示，**不完成，可以重试** |
| `api.str / api.ui / api.sfx / api.scene / api.map / api.spot` | 直接拿到地基对象 |

**最容易踩的坑**：`open()` 里播完对话忘了 `pass()`。这时玩家会觉得「点了没反应」。
失败重试的那种，走 `fail()`，不要 `pass()`。

### 6.2 过场：`steps` 词表

一段过场就是按顺序执行的时间块。每块是 `{ t:'…', ms:… }`：

| `t` | 字段 | 效果 |
|---|---|---|
| `fade` | `to:0\|1`, `ms`, `color` | 全屏淡入淡出（黑场） |
| `bars` | `on:true\|false`, `ms` | 电影黑边 |
| `card` | `key`, `who?`, `ms` | 底部字幕卡 |
| `title` | `key`, `subKey`, `ms` | 屏幕中央大字（开场那种） |
| `portrait` | `who`, `on:false` 收起, `side:'left'\|'right'` | 立绘滑入（找 A 的 `portrait.<who>`） |
| `flash` | `color`, `ms` | 白闪 |
| `shake` | `ms` | 画面抖 |
| `zoom` | `v:1.06`, `ms` | 画面推近 |
| `sfx` | `name` | 音效（`G.audio.play`） |
| `wait` | `ms` | 空等 |
| `clear` | — | 收掉当前字幕卡 |

跳过机制是免费的：空格/回车/Esc/点击跳过当前块，700ms 内再按一次跳过整段。
**演示的时候记得按两下跳过。**

完整示例见 `data/cuts/opening.js`（开场）和 `data/cuts/wumen-intro.js`（转场）。

### 6.3 你的自检

```bash
node tools/check-modules.mjs   # 玩法 id、过场文案 key、立绘有没有画
```

然后手测两个链接：`?map=wumen`（整关）和 `?cut=wumen.intro`（单段过场）。

## 7. 三方交界处的三条铁律

1. **不互相引用文件。** A 的文件里不出现 `G.mod.puzzle` 的名字以外的 C 的东西；C 的文件里不出现 A 的坐标。
2. **画面只经 `scene.vars`。** C 想「标签归位后画面变对」，就 `api.setVar('gridDx', 0)`；A 的画笔读 `scene.vars.gridDx` 决定画在哪。**C 不碰坐标，A 不碰判定。**
3. **文字只经 key。** 任何一个人写中文进 js，都算 bug。中文只在 `data/script.json`。

## 10. 报错对照表

| 症状 | 原因 | 修法 |
|---|---|---|
| 满屏 `⟪nodes.wumen.name⟫` | `data/script.json` 加载失败 | 检查 JSON 有没有注释/尾逗号；跑 `build-data.mjs` |
| `[mod] 缺少画笔：wumen.gate` | 地图里的名字和画笔登记不一致 | 两边字符串对齐 |
| `[mod] 缺少玩法模块：…` | `spots[].puzzle` 没有对应 `G.mod.puzzle` | 加模块或改名字 |
| 交互点了没反应 | `open()` 里忘了 `pass()`/`fail()` | 补上 |
| 进场没演过场 | `enterCut` 名字拼错，或 `seen.<id>` 已经是 true | 控制台 `G.save.flag('seen.wumen', false)` |
| 过场卡住不动 | 某一步 `ms` 特别大 | 空格可跳过；检查 `ms` |
| 立绘不出现 | `portrait.<who>` 还没画 | A 补画笔；或先忍 |
| 改了 `script.json` 不生效 | 忘了 `build-data.mjs`，或浏览器缓存 | 跑一遍 + 硬刷新 |
