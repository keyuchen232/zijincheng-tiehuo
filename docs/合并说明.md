> 结论先说：**已经没有任何冲突了** —— 模拟合并实测 0 冲突（见 §八），
> 剩下的事只是「把改动提交、推上去、让 GitHub 重新算一次」。

└── 16d50d1 … 27325ad（upstream，10 个提交）

upstream/main 在我们开工后又走了 10 个提交（PR#1 合的是我们上一版，

它们改的东西和我们重叠：

## 四、动手步骤

> 前提：先把工作区里**别人还没提交的改动**处理掉。
> 合并要求工作区干净，否则 `git merge` 会直接拒绝。

```bash
# 0. 看一眼有没有未提交的东西（有就先 commit 或 stash）
git status

# 1. 拿最新的 upstream
git fetch upstream

# 2. 确认基点没变（应输出 1e9f4e5…）
git merge-base --is-ancestor 1e9f4e5 upstream/main && echo ok

# 3. 把我们这一版切到独立分支上，别污染原分支
git switch -c feat/modules-sync chore/repo-normalize

# 4. 合并（预期只有 index.html 一个冲突）
git merge upstream/main

# 5. 解冲突：index.html 末尾两段都留，portraits.js 在前
#    （如果只提示 index.html，那就在编辑器里把两边的新增行都保留）

# 6. 验证
node tools/build-data.mjs        # script.json → script.js，顺带校验 JSON
node tools/check-modules.mjs     # 静态对账：所有 painter / puzzle / map / 文案 key
start.bat                        # http://127.0.0.1:8123/
#   依次点：开场动画 → 故事模式 → 午门关（?map=wumen 可直进）

# 7. 推上去
git push -u origin feat/modules-sync
```

### 如果第 6 步跑不起来

`node tools/check-modules.mjs` 是纯静态检查，读文件不启动浏览器，
可以单独跑、也不会污染仓库。**建议至少跑这一个**。

## 五、如果持有者还是不肯合：拆成三个 PR

这是最稳的做法，而且每个 PR 都能独立说明「为什么安全」。

**PR-1 · 文档（零风险，先合这个）**
```
docs/剧情更新.md  docs/关卡设计.md  docs/任务分工.md
docs/模块接口.md  docs/文案接手文档.md  docs/合并说明.md
.gitignore（删掉 docs 那行）
```
纯 markdown，不参与构建，合了不会改变游戏任何行为。
先合它，持有者就能看懂后面两个 PR 在干什么。

**PR-2 · 地基 + 纯新增模块（零冲突）**
```
js/str.js  js/mod.js  js/stage.js  js/cut.js  js/boot.js
css/cut.css
js/art/wumen.js  data/maps/wumen.js
js/mods/*.js  data/cuts/*.js
data/script.json
tools/build-data.mjs  tools/check-modules.mjs
```
一份新文件都不会覆盖旧文件。**唯一需要动的是 `index.html` 末尾那段 `<script>`。**

**PR-3 · 接线（可以只由持有者自己加）**
如果连末尾那段都不想让我们改，就让持有者在 `index.html` 的
`<script src="js/main.js"></script>` 后面手动贴这 14 行。
贴完刷新页面就是新主线；不贴，旧游戏一行代码都不受影响。

> 这套拆分的关键卖点，写进 PR 描述里：
> **合入后旧流程完全不接管。** `js/boot.js` 只在带 `?map=` / `?cut=`
> 或者模块自己接管时才生效；不带参数时，标题页、打铁花线、雅典线
> 的行为和合入前完全一样。这一句能消掉持有者 80% 的顾虑。

用 `git merge-file` 把「我们的工作区 / 共同祖先 `1e9f4e5` / `upstream/main`」三方合了一遍，

自己复现：

```bash
git show 1e9f4e5:index.html    > /tmp/b.html
git show upstream/main:index.html > /tmp/t.html
git merge-file -p index.html /tmp/b.html /tmp/t.html > /tmp/m.html
echo $?      # 0 = 无冲突；>0 = 冲突处数
```
